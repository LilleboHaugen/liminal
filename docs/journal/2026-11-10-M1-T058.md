## Decisions
- Spec changes that alter behaviour (reason for the `spec_version` bump):
  - `FrameAllocator::begin_frame` returns `()` instead of `&Arena`. A returned reference keeps
    the allocator mutably borrowed, so no other method could be called during the frame.
  - `Pool<T>` makes one reservation holding the block area and a `u32` free stack
    (`pool_size`, `pool_align`). Chosen over two reservations (one `Layout`, one `dealloc`, no
    partial-construction failure path) and over an intrusive list (impossible for `Pool<u8>`).
    `capacity_bytes` stays `capacity × size_of::<T>()` and excludes the free list.
  - Zero-size requests run check steps 1 to 3, then always succeed; the address is non-null and
    a multiple of the effective alignment, otherwise unspecified.
  - `AlignedBuf::new` tests the effective alignment against `MAX_ALIGN` (LIM-MEM-0003) and the
    size rounded up to it against `isize::MAX` (LIM-MEM-0002), as `Arena` and `Pool` do.
- Q1 of the spec is closed against the core spec v1.
- M1-T013 was not added to `depends_on` of M1-T025; the spec's §13 states the dependency through
