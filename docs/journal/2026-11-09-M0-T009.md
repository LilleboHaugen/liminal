## Decisions
- Policy tests use path crates and `--offline`, so they need no network. They are `#[ignore]`d
  (they need cargo-deny) and run on every push in the `deny` CI job instead of once by hand.
- The allowed licences are read from `docs/process/DEPENDENCIES.md` in the test, so the doc and
  `deny.toml` cannot disagree silently.
- `doctor`: a missing tool that a `ci` step needs is an error; Miri (no step yet) is a warning,
  so `doctor` passes on machines set up for M0.
- `yanked = "warn"`: yanking is not a security signal by itself; advisories cover security.
- Policy tests live in `xtask/tests/` (integration test): test code in `tests.rs` files and
  `tests/` is not measured by `cargo llvm-cov`, which is the repository's convention. A
  first version in `xtask/src/deny_policy.rs` counted its ignored test bodies as uncovered.

## Problems and traps
- cargo-deny's `--config` is a global option: `cargo deny --config X check`, not
  `cargo deny check --config X` (the latter is a usage error, exit 2).
- `allow-unwrap-in-tests` covers `#[test]` functions and `cfg(test)` modules only. Helper
  functions in an integration test file need `expect("test setup: …")`.
- Coverage on `main` measured 97.35 % (4888/5021) here, while the M0-T008 handoff reported
  97.56 % (4879/5001). Not investigated; this task does not lower it (97.39 %).
