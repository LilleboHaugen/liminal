## Problems and traps
- **Moved checkout.** The owner renamed the checkout directory (`rust-game-engine` → `liminal`).
  `cargo xtask` did not rebuild, and the binary's compiled-in root (`env!("CARGO_MANIFEST_DIR")`)
  pointed at the old directory: every step failed with "could not start …/bin/cargo" and
  LIM-XTASK-0001 with an empty path. Fix: `cargo clean -p xtask` (removes target artefacts only).
  M1-T010 item 1.
- **Mutation by copy-and-restore.** Restoring a mutated source file with `mv` from a `cp` copy
  gives it a modification time older than the mutant build, so cargo does not rebuild and the
  next test run uses the mutant binary. `touch` restored files (or `git checkout` them) before
  building again. In this session the M4 run also carried the M3 mutant in the library; the
  failure it reported (exit 1 instead of 2) comes only from M4.
- The working tree holds the owner's uncommitted URL edits (`Cargo.toml`, `STATUS_NOTES.md`,
  M0-T001, M0-T007). This session did not commit them.
