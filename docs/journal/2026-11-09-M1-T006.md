## Decisions
- **Trigger set: `push` on every branch, no `pull_request`.** Reason: task branches are merged
  to `main` locally by the reviewer, who needs the branch's own CI run (WORKFLOW.md §8), so
  `push: branches: [main]` + `pull_request` would leave task branches without CI unless every
  task opened a pull request. With both triggers, a branch with an open pull request runs all
  six jobs twice per push (observed on PR #1: one `push` and one `pull_request` run for the same
  SHA, in different concurrency groups because `github.ref` differs, so `event_name` in the group
  never mattered). The only extra a `pull_request` run checks is the merge with `main`; the
  reviewer already runs `cargo xtask ci` on the merge result, and the `main` push run checks it
  after the merge. A pull request still shows the `push` run of its head commit as its checks.
- **Action updates: Dependabot version updates, monthly, grouped.** Reason: a machine signal
  for outdated pins instead of a cadence that depends on an agent remembering it; GitHub-native,
  no crate dependency, keeps SHA pins and rewrites the version comment. A Dependabot pull request
  is handled through a task like any other change, not merged on GitHub. Not covered: Dependabot
  *security* alerts for actions need the repository setting "Dependabot alerts" (owner's
  choice; not checked or changed by this session). Cargo dependencies are deliberately not in
  `dependabot.yml` (new crate versions go through ADR/`cargo xtask deny`).

## Problems and traps
- The M0-T007 failure experiment also failed `clippy` (`dead_code`); a future failure experiment
  should change only what the targeted step checks, e.g. mis-indent an existing line (task note,
  no work).
- `cancel-in-progress: true` also applies to `main`: two merges pushed in quick succession cancel
  the earlier `main` run, so "CI green on `main`" is then observable only for the later commit.
  Not changed (out of scope); worth a decision if merges become frequent.
- `origin` in this checkout still points to `LilleboHaugen/rust-game-engine.git`; GitHub
  redirects ("This repository moved") to `LilleboHaugen/liminal`. Pushes and `gh` work; not
  changed (local configuration, not part of the repository).
- `gh run list` on its own can hide a run that is still `queued`; on a busy day macOS arm64
  runners were not acquired for 15 min and the job was cancelled (not a test failure). Check job
  annotations before treating a red run as a code failure.
- Dependabot's first check runs after `dependabot.yml` reaches `main`; this session could not
  observe a Dependabot pull request.
